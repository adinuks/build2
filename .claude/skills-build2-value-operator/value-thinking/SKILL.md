# Value Thinking

Thinking is the first move of a Value Operator. Before anything is built, know the human and name the problem. A sharp Problem Statement can save 45 minutes of building the wrong thing.

AI is the thinking partner, not the replacement. Use it to expand what the student wrote, then the student reads every line and deletes anything that does not feel true. The judgment is always theirs.

## What do you want to achieve?

Ask the student which of these fits. If unsure, start with the first.

| I want to... | Do this | Read |
|---|---|---|
| Understand the real need behind a problem area | Full need finding: the three questions, map the humans, find the job, plan research, reach an insight | `ref/need-finding.md` |
| Write a Desire Profile and a Problem Statement quickly | Class mode: steps 7 and 8 only, from what the student already knows | `ref/need-finding.md` |
| Check my thinking for human behaviour and my own bias | The human nature lens: needs, effort, perception, biases | `ref/human-nature.md` |

## Rules for every mode

- **One real person.** Start from a specific human the student knows or has observed. Not a persona, not "users".
- **A complaint is not a problem.** A problem has a who, a what and a why. Use this form:
  *[Who] struggles with [what] because [why]. Every solution they have tried fails because [reason].* No solution hiding inside it. The moment "using an app" or "by tracking" appears, it has left the problem space.
- **Then the HMW.** *How might we help [who] to [do what] so that [outcome]?* It must be about the problem, open enough to explore, specific enough to be useful.
- **Nothing invented.** Every need, quote and number comes from the student or their research. Mark gaps `[to confirm]`.
- Plain language. Short sentences. No em dashes.

## Gate before moving on

Do not hand off until:
- Every line of the Desire Profile feels true to the real person. Someone who knows them would recognise them.
- The Problem Statement is one sentence, sharp, with no solution inside.
- The pains are specific enough that a solution becomes obvious, and the gains are specific enough to test.

If a check fails, say which and return to that step.

## Save and hand off

Write `need-finding.md` in the project folder. Add a three-line summary to `intent.md` (create it if missing): the person, the Problem Statement, the HMW. Then suggest `value-creation`.
