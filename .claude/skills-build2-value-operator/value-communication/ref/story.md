# The story: Problem, Agitation, Solution

Every framework is this spine in different clothes. Find the story before any format.

## Where the raw material lives

| Spine part | Usual source |
|---|---|
| Problem | Problem Statement, Desire Profile (context, jobs to be done) |
| Agitation | Desire Profile pains, research quotes, audit findings, the "old painful way" in the press release |
| Solution | Concept, press release, prototype, what was seen when it was tested |

If a part has no material, say so and point to the skill that fills it.

## Write it

Save `story-v1.md` using `ref/story-template.md`. One short paragraph each for Problem, Agitation and Solution in the student's own words, each with an evidence line (a quote, a number, a finding, a screen). Then the ask. New versions are `story-v2.md`, never an overwrite.

## The three tests

**Agitation test**
- One specific person in one specific moment, not "users"?
- Says what the problem costs them (time, money, effort, a feeling, a risk) every day?
- Says why the current ways fail?
- Has evidence from the student's own work?
- Would the person recognise themselves?

**Solution test**
- Answers the exact Problem Statement, not a bigger one?
- A clear moment where the problem gets resolved?
- Proof (prototype, test, audit, press release line)?
- One trade-off or limit stated honestly?

**Three-sentence test**
Read aloud: "[Who] is stuck because [problem]. Every day it costs them [agitation]. So we built [solution], and now [what changes]." If a stranger would understand and care, the story works.

## Map and trim

Lay the spine across the chosen framework's steps (`ref/frameworks.md`). Show a table: step, what goes in it, spine part. Trim to the time available, about one beat per minute, fewer with discussion.

## Make it theirs

Read it aloud. Edit anything that does not sound like the student. Add one thing the AI missed. Remove one thing that feels weak. They are presenting their thinking, not the AI's draft.
